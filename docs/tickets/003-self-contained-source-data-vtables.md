# 003 Make `src/` self-contained: data, literals, vtables, traps (the gate for every other build)

Area: port-gate | Effort: XL | Impact: very high | Depends on: none (already in flight; memory "standalone-independence")

## Summary

A clang build cannot link at the original's fixed addresses and cannot copy the original's data image. Today the relinked exe
does both. This ticket is the same work the maintainer already tracks as "standalone independence"; it is listed here because
it is the single hard gate for the portable engine: without it there is nothing to port.

## Evidence

From `work/relink/standalone/build.json` (2026-11-01) and `docs/data_history.json` (2026-10-27):

- glue closes 1,915 unresolved symbols: 1,412 **data labels**, 483 aliases, 20 left. Pointers relocated: data 5,216, code->ours 2,032,
  code->crt 52, code->**trap** 304. 248 trapped code addresses (all provably unreachable: `docs/standalone_traps.md`).
- vtables: 8 slots rewritten in 68 vtables, **512 vptr stores moved to the original's table**, 45 vtables skipped as suspect,
  1,032 slots bound by forwarding stubs, 45 placeholder virtuals bound by the glue.
- data items (last measurement): defined in source 45; generated by cl (literals, constants, vtables) 2,010; **borrowed 787**;
  **reached through pointer tables 790**; library (CRT) 538. Bytes still to define: initialised ~208 KB (.rdata 23.7 KB,
  .data 184.7 KB) and the .bss pools, 143.9 MB total (`.data` VirtualSize 0x893db94).
- The linker is told `/FIXED:NO` but code is still position-bound: `Screen_s261e0::tick` and friends reach globals as
  `g_game_s261e0 + 0x1a1a4`, and annotations like `extern int g_x; // 0x5e2464` resolve through `resolve_map.json`.
- The 2026-10-30 maintainer rule: no new literal address, vtable placeholder, or glue alias.

## Detailed plan

1. Classify the 1,577 remaining items (`tools/relink/data_coverage.py --json`): (a) const tables (string tables, key tables,
   opcode name tables, vtables of classes we do declare) -> `static const` arrays in headers/TUs generated by a one-shot extractor
   from `work/mb.analysis.bin` (the **generator** may read the exe; its output is committed source), (b) mutable globals
   with initialisers -> ordinary definitions, (c) pools (.bss) -> `static` arrays or, better, heap-allocated at startup (ticket 016),
   (d) pointer tables -> arrays of `&symbol`.
2. Replace every `// 0xADDR` extern with a real definition in the owning TU; gate in `build.py` already refuses duplicates.
3. Delete placeholder virtuals: make base classes declare the real slot layout from the original's vtables (the 45 suspect vtables
   list in `build.json -> vtable_report.skipped` is the work list; most are `Rec*`/`Item*` record families with 3 of 9 slots agreeing).
4. Remove traps by defining the 248 EH funclet targets' owners (they vanish once the owning functions' own unwind tables are used: all are
   `eh-unwind`/`eh-catch` of functions we compile ourselves, 134 of 248) and by dropping the CRT-range ones (114) that libcmt supplies.
5. Remove `glue.py`'s `mb_data.obj` from the link; remove literal fix-up and vtable fix-up passes. Each removal is a `build.py`
   gate that goes from "allowed" to "fail".
6. The portable build then needs only the same source: no `resolve_map` annotation parsing (addresses stay as comments).

## Code sketch (extractor output shape)

```cpp
// src/game/tables/key_names.gen.cpp  -- generated by tools/data/extract_table.py 0x5a1b40 --type const char* --count 0x80 (committed)
extern const char* const g_key_names[0x80] = { "", "escape", "1", /* ... */ };   // 0x5a1b40
```

## Risks

- Reads of "unknown" data that the game never writes but the harness assumes at the original address: wrong table size = silent
  corruption. Mitigation: `data_size_audit.py` (exists) plus a debug mode comparing definitions to the image bytes.
- Pools sized from the image (126.9 MB .bss "borrowed") hide real counts; do not copy sizes, derive them from code (ticket 016).

## Acceptance

- `build.json`: traps 0, literals 0, vtable rewrites 0, glue data 0; the game boots to the menu, plays a battle.
- `data_coverage.py`: borrowed from image 0.

## Effort

XL (8-16 wk; mostly mechanical + review; parallelisable per module).
