# 015 Modding: documented data formats and tooling (BRF/TRF, SCO, saves, module tables)

Area: modding | Effort: M | Impact: high | Depends on: none to start (readers exist in src/); 006 for save portability tests

## Summary

The decomp already contains reference readers and writers for the engine's formats. Turn them into specs plus standalone tools (import/export, validators), so modders can work without the 2008 tool chain.

## Evidence

- **BRF (binary resource) / TRF (text twin)**: `resmgr::load_pack` 0x41e150 (src/rgl/core/resmgr.cpp:1183): opens `CommonRes\<name>.trf|.brf` (or `<module>\Resource\`); if `g_use_text_res` and the `.trf` is newer it parses the text, then **writes the `.brf`** with `bin_writer`. Block tags dispatched in `load_stream` (resmgr.cpp:1100-1170):
  `mesh`, `material`, `shader`, `texture`, `body`, `skeleton`, `skeleton_anim`. The TRF text format is therefore a built-in text *input* path for every BRF block (a reader exists: `text_reader`; whether a TRF *writer* exists is unverified - `text_stream` has write slots, check before promising brf2trf).
  CommonRes holds 148 BRF files (76 MB); Native has `Modules/Native/Resource/` plus data tables.
- **Streams are typed**: `stream_base` slots `w_int/w_float/w_u64/w_i64/w_bool/w_cstr/w_tstr` and mirrored readers (src/rgl/stream.h): all binary formats are therefore width-explicit, which makes them portable to 64-bit.
- **SCO scene files**: `Modules/Native/SceneObj/*.sco` (e.g. `scn_castle_1_exterior.sco`), written by `scenes[idx].save(&w, 0)` (mission_5.cpp:1066) and `SceneObj_s27c90::save`, grids via `grids.save(&rec->stream_a)`.
- **Saves**: `sg%d%d.sav` paths (5 sprintf sites), written by `SavePanel`; `save_path` helper (crash C5 in docs/crashes.md shows the path buffer contract).
- **Module tables**: 42 text files per module (Native listing), sizes tiny; parsed with `split_line`/`Config::load_file`-style readers; 8-bit codepage text.
- **Data/**: `item_modifiers.txt, flora_kinds.txt, ground_specs.txt, skyboxes.txt, mission_types.txt, falls.txt, font_data.xml, skeleton_bodies.xml (TinyXML), sound_samples1.txt`.
- **Textures**: DDS (370) + TGA (3); standard formats.
- Existing helpers: `tools/ghidra` and `tools/relink` are binary-analysis tools; there is no format tool yet.

## Detailed plan

1. Spec documents (`docs/formats/brf.md`, `sco.md`, `sav.md`, `module_txt.md`) generated by reading the code (each block's reader is the grammar) and validated by round-trip tests on the user's own data (no game data in the repo).
2. `tools/mbfmt` (C++ or Python) with subcommands: `brf2trf`, `trf2brf`, `brf2gltf` (meshes, skeletons, animations; materials -> glTF PBR approximations), `gltf2brf`, `sco dump`, `sav dump/diff`, `module check`. Reuse the engine's own readers via a `libmbformats` target (portable build) to avoid divergence.
3. Verification: for every Native BRF, `brf -> trf -> brf` is byte-identical (if the TRF writer is missing, write it: it is the mirror of `text_reader`); for SCO and SAV, load+save yields identical bytes.
4. Texture tooling: nothing custom; document supported DDS formats (DXT1/3/5, A8R8G8B8, R5G6B5...) from the loader in 009.
5. Hot reload in the portable engine: watch the module folder, reload BRFs and module tables on change (`load_pack` is re-entrant: it does `all.resize(0,0)` per call).
6. Version fields: add an optional format-version tag in new files so future extensions (more bones, larger counts) do not break old readers.

## Code sketch

```
$ mbfmt brf2trf CommonRes/armors_b.brf armors_b.trf        # engine's own reader/writer via libmbformats
$ mbfmt brf2gltf CommonRes/armors_b.brf --out armors_b.glb  # per-mesh nodes, skeleton -> skin, morph keys
$ mbfmt module check Modules/Native                          # runs the validators of ticket 014 headless
```

## Risks

- Lossy glTF export of tangent/color/morph data; keep TRF as the lossless path.
- Mod authors' tools (OpenBRF) already exist in the community; match its expectations rather than reinventing: note OpenBRF compatibility as an open question (not verified here).
- Save game compatibility across 32/64-bit and across the old/new engine: version-tag and test with 32-bit saves (006).

## Acceptance

Round-trip tests pass on all Native BRF/SCO files and a sample save; `mbfmt` documented; `docs/formats/` exists.

M (4-6 wk).
