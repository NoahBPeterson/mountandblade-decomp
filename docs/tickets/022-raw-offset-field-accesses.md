# 022: Raw-offset field accesses: name the field

Opened 2026-11-16. Maintainer: "(char*)troop + 0x48 ... is a really shitty way of doing `troop.field`. Just name the field
dude! Triage this." Effort: M (E and V: days; N: rides on ticket 021). Impact: high for the 64-bit build (006) and for
modding (019): a raw 32-bit offset reads the wrong memory once pointers are 8 bytes, a member access does not.
Related: 006 (layout-neutral structs), 019 (idiomatic source), **021 (padding and offset-named fields, written in
parallel: the N rows below are mostly its work)**.

Status (2026-11-16): triage done. Fixed 437 of the 4575 baseline sites (E 365 of 770, N 36, U 25, X 11), all
byte-neutral; 47 kept on purpose (table below). Open: E 369, N 1135, V 43, U 374. `work/commit_frozen.sh` over the
batch: build OK, data_values / vtable_gate clean, 5006 / 5006 manifest rows byte-exact, menu smoke OK (PASS).
x86_64 burndown unchanged (19 / 187 TUs compile, 9065 errors before and after: the remaining blockers are 006's
layout asserts).

## The sites

`docs/tickets/022-offset-sites.tsv` lists every site, one row each (generated by `tools/port/offset_sites.py`, baseline
main 9a59164e). It reads clang's AST of every src/ TU in the portable linux-i686 configuration, not the text, so macro
uses (`WD_FLD(int, 0xe8)`, `GDP(..)`, `SC`) and `char* e = (char*)p; e + 0xe8` aliases count, and every site has its
record type and the i686 record layout to check the offset against. Kinds:

| kind | shape | sites |
|---|---|---|
| A | `(char*)X + 0xNN` (however it is then dereferenced; also through a `char*` local) | 1535 |
| B | `((T*)X)[k]`: a scalar view of a record, indexed | 101 |
| C | `((U*)X)->f`: a record reinterpreted as another, unrelated one (`((GameX*)g_game)->main_party`) | 2299 |
| D | `*(T*)&X->field`: a field's address reinterpreted (`*(Pawn**)&g_mission->f65e4`) | 640 |

The plain-text `rg '(char*)X + 0x'` count is 310 lines; the AST count of kind A is larger because one macro or one
line holds several sites and the `char*`-local and macro forms do not match that pattern.

## How each fix is checked

docs/codegen.md 5.6 warns that a layout-neutral header change can move the register allocation of functions that only
include it. So every edit here was checked stronger than per-row: each touched TU, and for a header every TU that
includes it (dependency list from the port build), is compiled with MSVC before and after, and every function symbol's
code and relocations (local label numbers normalised) must be identical. Then tools/matching/chk.py on the touched
rows for the record. One `work/commit_frozen.sh` run over the batch at the end.
